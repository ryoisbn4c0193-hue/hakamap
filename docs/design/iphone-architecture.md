# iPhone版の基本設計

更新日: 2026-10-23

## 適用範囲

[業務要件](../requirements/iphone.md)に基づくiPhone縦向きの参照専用アプリ。
初期版の製造を完了し、利用者による実機テストへ進む。
Windows版の既存エクスポート機能と保存形式は変更しない。
技術上の判断は既存実装に合わせて進め、利用者への質問は業務要件に関わる判断に限る。

## 構成

- `mobile/`にExpo SDK 58、React Native、TypeScriptで実装する。
- 標準UIはReact Native、配置図はReact Native SVGとPanResponderで描画・操作する。
- 日本語変換の開始・確定を判定する検索欄はExpo DOMを使用する。
  表示エンジンは`useExpoDOMWebView: false`で既存の`react-native-webview`を選ぶ。
  Expo Goで報告された`DomWebView`のネイティブビュー参照エラーを回避するためである。
  HTML・JavaScriptをアプリへ同梱し、外部URL・CDNへアクセスしない。
- ファイル選択はExpo DocumentPicker、選択ファイルの読み込み・一時コピー削除は
  Expo FileSystem、永続保存はExpo SQLiteを使用する。
- APIサーバーは起動しない。検索・地図表示・通常の参照は端末内で完結する。
- 配色と地図の状態色はWindows版に合わせる。

## Windows版からのデータ受け渡し

利用者の指示により、Windows版の既存`.hakamap`をそのまま取り込む。
専用エクスポート・中間ファイル・変換ツールは使用しない。
ZIPベースの形式は既存の`ProjectArchiveService`と整合させる。

| 収録ファイル | 取り込み時の扱い |
| --- | --- |
| `manifest.json` | `formatVersion: 1`、`archiveType: export`、墓地ID、作成日時、一覧・サイズ・SHA-256を検証 |
| `project.json` | `schemaVersion: 1`。墓地、配置図、墓所、人物、背景・アセット参照を読む |
| `assets/backgrounds/` | 参照している背景画像を表示用に保持する |
| `assets/attachments/` | 整合性を検証するが、参照用データへ保存しない |

- マニフェストの全収録ファイルについてサイズとSHA-256を照合する。
  不要な添付も破損していれば受け入れず、現在のデータを保持する。
- 未宣言ファイル、重複パス、絶対パス、上位参照、バックスラッシュを拒否する。
- ZIPの件数・展開量・圧縮率、JSONの版、IDの一意性、人物・背景・添付の参照を検証する。
- 検証後に墓所名・家名、人物氏名、エリアと墓所の形状、背景画像・配置を抽出する。
  添付、備考、戒名、編集履歴、元アーカイブは端末内の参照DBへ保存しない。
- 表示するデータ作成日時はWindowsエクスポートの`manifest.createdAt`とする。
  UTCで保持し、端末の地域設定で表示する。取り込み日時への置き換えはしない。
- PDF背景はWindows版で既にPNG化されているので、そのPNGを使用する。
- 背景の移動・回転・縦横倍率、表示対象エリアの色と順序を維持する。
- 初期版の上限は圧縮32MiB・展開48MiB・5,000墓所・20,000人物・背景4096px。
  超過時はエラーにし、画像や墓所を黙って省略しない。

## 取り込みと保存

1. iPhoneの「ファイル」から選択したファイルをアプリのキャッシュへコピーする。
2. アーカイブとJSONを検証し、必要な情報だけの保存候補をメモリ上へ構築する。
3. 背景がある場合はネイティブ側で画像を読み込めることを確認する。
4. 既存データがある場合は全件置き換えを確認する。拒否・キャンセル時は更新しない。
5. 地図と背景を1レコードとして、SQLiteの単一更新文のトランザクションで置き換える。
6. 成功後に画面のデータを切り替え、検索を空欄・地図を全体表示へ戻して完了を案内する。
7. 成功・拒否・失敗いずれの場合も、一時コピーの削除を試みる。

旧行を削除してから新規挿入する処理は行わない。検証失敗・保存失敗時は旧データを保持する。
SQLiteのWALを使用する。実機の容量不足・強制終了に対する動作は実機テストで確認する。
ハッシュは破損検出用であり、送信者を認証する署名ではない。

## 検索と表示状態

- 墓所名・家名は`graves.name`、人物氏名は`people.name`を墓所IDに紐づける。
- 「すべて」「墓所名・家名」「人物の氏名」を切り替え、初期値は「すべて」とする。
- NFKC、大小文字、Unicode空白、かなを正規化して部分一致を判定する。
- 日本語変換中は結果を維持し、確定後に250msの待機で連続入力をまとめて更新する。
- 一致墓所をIDで重複除去して赤く強調する。回転を考慮した外接矩形から、
  検索欄・ツールバー・キーボードを除く領域に一致墓所が収まるよう調整する。
- 0件・検索解除時は位置・倍率を維持し、解除時は強調を取り消す。
- 名前表示設定は地図データと別に保存する。初回は表示、以降は前回設定を引き継ぐ。
- 起動時は検索欄を空欄、地図を全体表示とする。

## 墓所情報の参照

`MapView`の単一指タップを判定し、回転した墓所も含めてIDを通知する。
親画面でそのIDの墓所を選択し、`GraveDetails`に保存済みの墓所名・人物氏名を渡す。
人物氏名の検索一致表示は検索と同じ正規化を使用する。
新たな情報を端末へ追加する変更ではなく、既存の参照データを画面へ表示する変更とする。
データの置き換え成功時には選択中の墓所を解除し、古い詳細を表示しない。

## 製造と実機テストの境界

製造完了はソース実装・自動検査・iOS向けJS/DOMバンドル生成までを指す。
iOSネイティブコンパイル、署名済みIPA、TestFlight配布、実機テストの完了を含まない。
EASのビルドプロファイルを用意した。配布時はExpoプロジェクトとApple署名設定が必要。
実機テスト項目は[検証手順](../verification/iphone.md)、検査結果は
[実装状況](iphone-implementation.md)を参照する。
