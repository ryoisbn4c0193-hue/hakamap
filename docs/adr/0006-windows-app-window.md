# ADR 0006: Windows版をブラウザの専用ウィンドウで表示する

日付: 2026-10-27
状態: 採用。Windows実機での受入確認は未実施。

## 背景

利用者が通常のブラウザタブとの混同を避けるため、専用ウィンドウを希望した。
タスクバーをHakamapの正式アイコンで区別でき、クリックで既存画面を表示・最小化復元できること、
ピン留めから再実行しても画面・バックエンドを重複起動しないことが確定条件である。

## 決定

- インストール版ではEdgeを優先し、未導入ならChromeのアプリモードで開く。
- 通常のブラウザとは別の`HakamapData/browser-profile`を使用する。
- 新しい依存を追加せず、既存のJNAでウィンドウを識別・前面化する。
- 起動したプロセスと専用プロファイルのプロセスに属する、新しいHakamapウィンドウだけを対象にする。
- ウィンドウにAppUserModelID `jp.hakamap.Desktop`、Hakamap.exeへの再起動コマンド、
  正式アイコンのリソースと表示名を設定する。ブラウザのURLをピン留めの再起動先にしない。
- デスクトップ・スタートメニュー・ピン留めのショートカットも、対象が現在のHakamap.exeと一致する場合だけ同じAppUserModelIDへ揃える。
- 既存画面は再読み込みせず前面化する。最大化状態は維持し、最小化の場合だけ復元する。
- 再起動要求元から既存バックエンドへ前面化の権限を渡す。画面再作成の待機に合わせ再表示要求のタイムアウトを延ばす。
- 本体の「終了」では管理対象の専用画面にも通常のウィンドウ終了要求を送る。
  ×だけでバックエンドも終了する変更は行わない。
- Edge・Chromeがどちらもない場合は導入案内を表示する。通常タブへの自動退避を完了扱いにしない。
- IDEなどの非インストール起動では従来のブラウザ表示を維持する。

## 検証と制限

専用画面の再利用・再作成・プロセス重複防止・起動引数は自動検査する。
JNAのウィンドウ識別はWindowsのGUI利用可能なテスト環境で検査する。
タスクバーのグループ化・ピン留め・最小化復元はWindows実機で確認し、未確認のまま受入完了としない。
特にブラウザ更新によるウィンドウ属性の変更、Windowsの前面化制限、既存ピン留めの互換性を確認する。
